# FieldPilot

СППР управления фондом скважин нефтегазового месторождения. Kotlin + Spring Boot, SQL, Smile ML, аналитическая панель и Docker Compose. Учебный MVP рассчитывает приоритет внимания и портфель мероприятий на 30 суток. Данные демонстрационные, нефтяная составляющая моделируется отдельно от газа.

## Запуск

```sh
docker compose up --build -d
```

Открыть **http://localhost:8081**. Первый запуск обучает модель и создает шесть демонстрационных скважин. PostgreSQL сохраняет карточки, мероприятия, модели, журнал обучения и снимки решений в отдельном томе `fieldpilot-db`. `docker compose down` останавливает сервисы, данные сохраняются.

Настройки при необходимости: скопировать `.env.example` в `.env`. Приложение доступно только на localhost; авторизация в учебном MVP не реализована. Для внешнего доступа нужны аутентификация и разграничение прав.

Без Docker: JDK 21, `./gradlew bootRun`. По умолчанию используется файловая H2 в `./data`, порт 8081. Проверка: `./gradlew test`, `python3 scripts/smoke.py` при запущенном демо. Открывать в IntelliJ IDEA именно папку **FieldPilot** как Gradle-проект.

## Что можно сделать в интерфейсе

- Добавить, изменить и удалить скважины: признаки для прогноза, ответственный, качество данных, допуск, технологический риск и срочность.
- Для каждой скважины задать затраты, трудозатраты, прирост и риск-резерв пяти действий: эксплуатация, режим, ГТМ, ремонт, остановка.
- Изменить попарные сравнения AHP; увидеть веса, CR, матрицы альтернатив и рейтинг.
- Изменить три сценария и их вероятности; сравнить стратегии по Байесу, Вальду, Сэвиджу и Гурвицу.
- Менять бюджет и бригадо-дни; получить точный оптимум в пределах лимита поиска.
- Просмотреть экспертные правила, факты их срабатывания и рекомендации по каждой скважине.
- Выполнить отдельный прогноз, увидеть метрики, коэффициенты, вклады признаков и обучающие периоды.
- Загрузить CSV, обучить модель вручную, проверить журнал планового обучения, переключить сохраненную версию.
- Сохранить неизменяемый снимок решения, сравнить два снимка и выгрузить JSON.

## Восемь практик

| Практика | Реализация | Результат |
|---|---|---|
| 1. Постановка | Реестр, признаки, пять действий, ограничения | Формальная задача выбора одного действия для каждой скважины |
| 2. AHP | `AhpCalculator`, редактируемая матрица 4×4 | Приоритет внимания и проверка CR ≤ 0,10 |
| 3. Неопределенность | `ScenarioAnalyzer`, три состояния внешней среды | Исходы стратегий, ожидаемый эффект, гарантированный эффект, сожаление |
| 4. Оптимизация | `PortfolioOptimizer`, точный поиск с отсечениями | Максимум ожидаемого эффекта при бюджете и бригадо-днях |
| 5. База знаний | `KnowledgeEngine`, R1–R6 | Проверка допуска, качества, диагностика, объяснения |
| 6. ML и BI | Smile Ridge, временная выборка, панель | Средний базовый дебит на следующие 30 суток |
| 7. Рекомендации | `AnalysisService` | Действие, стоимость, эффект, причины и ограничения |
| 8. Итоговая СППР | Spring API, панель, PostgreSQL, Docker | Воспроизводимый прототип и журнал решений |

Для каждой практики цепочка: **постановка → метод → результат → интерпретация** приведена в [паспорте](docs/PASSPORT.md). Архитектура: [ARCHITECTURE.md](docs/ARCHITECTURE.md), ML: [ML.md](docs/ML.md), API: [API.md](docs/API.md), демонстрация: [DEMO.md](docs/DEMO.md).

## Контрольный пример

Бюджет 3,5 млн ₽, ресурс 12 бригадо-дней. W06 не имеет допуска, поэтому допустима только остановка за 0,2 млн ₽ и 1 бригадо-день. Эта остановка уже включена в базовую стратегию.

Оптимальный набор: **W01 ГТМ, W02 ГТМ, W03 ремонт, W04 режим, W05 эксплуатация, W06 остановка**.

- Общие затраты: **3,5 млн ₽**, включая обязательную остановку. Дополнительные затраты к базе: **3,3 млн ₽**.
- Прирост в центральном сценарии: **550 т**, добыча **3580 т** вместо **3030 т** за 30 суток.
- Ожидаемый дополнительный экономический эффект: **2,98225 млн ₽**.
- Исходы неблагоприятного / центрального / благоприятного сценариев: **0,145 / 3,030 / 5,724 млн ₽**.
- Приоритет внимания AHP: W03 → W02 → W01 → W05 → W04. W06 рассматривается отдельно как обязательная остановка.

Тест сравнивает результат оптимизатора с независимым полным перебором. Обязательное действие нельзя заменить более прибыльным без изменения подтвержденного допуска.

## Границы модели

ML прогнозирует базовую добычу, **эффекты вмешательств задаются экспертом** с учетом простоя. Коэффициенты регрессии и объяснения не доказывают причинность. Метрики на синтетике не характеризуют точность на реальном месторождении.

Рассматриваются до 12 скважин и пять действий на скважину. Лимит точного поиска — 500 000 узлов; при превышении возвращается ошибка, приближенное решение не выдается как оптимальное. Не учитываются газовый баланс, взаимовлияние скважин, закачка, система сбора и календарь бригад. Технологический допуск вводит специалист; приложение не управляет оборудованием.

AHP определяет приоритет внимания, экономический оптимизатор решает иную задачу. Высокий приоритет не означает, что действие обязательно войдет в ограниченный портфель. Реализация однопроцессная; распределенное плановое обучение для нескольких реплик не предусмотрено.

## Технологии

Kotlin 2.3.21, Spring Boot 4.1.2, JDK 21, Gradle Wrapper, Spring JDBC, PostgreSQL 17 / H2, Smile 4.4.2 RidgeRegression. Клиент — HTML/CSS/JavaScript без внешних CDN. Одна публичная сущность в одном файле. Python используется только в дополнительном smoke-скрипте, сервер и ML полностью на JVM.
